# Agent Buddy 使用手册

> 项目介绍和截图见 [README](../README.md)。这里是各功能的详细说明。

把 Claude Code、Codex、DeepSeek Harness 等 AI 编程 Agent 的工作状态和 [magpie](https://github.com/yetone/magpie) 的面板显示在一块 ESP32-S3 触摸屏上。

首页二选一：

- **Agent Buddy**：Clawd 像素小人（或 Codex 宠物、DeepSeek 小鲸鱼）随 Agent 的动作切换动画，右侧显示 5 小时 / 7 天剩余额度。
- **magpie**：还原 magpie 菜单栏面板的 Agent / 额度 / 用量 / 路由四页，口径与 magpie 一致；标题栏喜鹊 logo 的点头扇翅、路由页光点飞行等动画照 magpie 源码还原。

硬件：Guition **JC4827W543**（ESP32-S3 N4R8，4.3" 480×272 NV3041A QSPI 屏，GT911 电容触摸）。电脑：macOS 或 Windows 10/11。

## 快速开始：新板子 / 新电脑

一条命令完成全部配置：装 Python 环境 → 注册 Claude Code / Codex / DeepSeek Harness 的 hooks → 检测板子 → 需要时烧录固件 → 开机自启 → 启动并自检。不需要装 Arduino，固件是 `firmware/` 里预编译好的。

1. 用 **能传数据的 USB-C 线** 把板子连到电脑（有的线只能充电，连上后电脑认不出设备）。
2. 下载本项目（`git clone` 或下载 ZIP 解压），然后：
   - **macOS**：终端里运行
     ```bash
     ./setup.sh
     ```
   - **Windows**：双击项目根目录的 `setup.cmd`（或在终端里运行 `setup.cmd`）
3. 按提示回答几个问题（都有默认答案；加 `--yes` 全部用默认）。完成后屏幕会弹出一条「欢迎回来」测试通知。
4. 重启已经打开的 Claude Code / Codex / dsh，让 hooks 生效。Codex 提示审核 / 信任新的 hook 时同意即可。

setup 可以重复运行，已经配好的步骤会跳过。它会自己判断板子的情况：

| 情况 | setup 怎么做 |
|---|---|
| 新板子（出厂固件） | 询问后烧录固件（默认烧） |
| 板子已经是本固件，版本相同 | 跳过烧录，只配电脑这边：**换新电脑时就是这种情况** |
| 板子固件比 `firmware/` 里的旧 | 询问是否升级；板子上的设置（声音、Wi-Fi、屏幕校准、雷达座位）保留 |
| 仓库换了位置 | 旧路径的 hooks 自动换成新路径 |

常用参数：`--no-flash`（不烧录）、`--flash`（一定烧录）、`--erase`（烧录前整片擦除，清空板子上的设置）、`--autostart` / `--no-autostart`。

修改 `~/.claude/settings.json`、`~/.codex/config.toml` 之前都会在原位置备份一份（`*.bak-agent-buddy-*`）。卸载：`bridge/buddy uninstall`。

### 配件接线（可选）

都不接也能用：没有喇叭就不出声，没有麦克风就靠电脑键鼠判断你在不在，没有雷达就看键鼠空闲时间。

| 配件 | 接到 | 说明 |
|---|---|---|
| 2030 喇叭（8Ω 0.5–2W，1.25mm 2P） | 板载 **Speak** 口 | 板载功放 NS4168：BCLK 42 / LRCK 2 / DOUT 41，直接插 |
| INMP441 麦克风 | **P3** 口：SCK→IO6、WS→IO7、SD→IO15，L/R→IO16；VDD 3.3V / GND 取 P4 | IO16 由固件拉低，选左声道 |
| HLK-LD2450 毫米波雷达 | **P1** 口：+5V、GND、雷达 TX→板子 RXD（IO44）、雷达 RX→板子 TXD（IO43） | 256000 波特率；TX / RX 接反了固件会自动换过来试 |
| 单节锂电池（3.7V，1.25mm 2P） | 板载 **BAT** 口 | 先量好极性再插；插上后按一下 **SW1** 开机（电池保护断开时喇叭会「滴滴」响）；插着 USB 时顺便充电 |

接好后在板子的 **设置页** 标定雷达座位、调音量；用 `curl -X POST '127.0.0.1:47823/ui?scan=1'` 扫描接上的模组（结果在 `bridge/buddy logs`）。

### Windows 与 macOS 的差别

| 功能 | macOS | Windows |
|---|---|---|
| 语音播报 | 系统 `say`（Tingting 普通话） | 系统自带 SAPI，优先选中文语音（中文版 Windows 自带 Huihui / Yaoyao；英文版需在「设置 → 时间和语言 → 语音」添加中文语音） |
| 打字检测 | 系统累计按键计数（无需权限） | 低级键盘钩子，只计次数、不记录按了哪个键 |
| 电脑麦克风占用（开会） | CoreAudio | 系统「麦克风隐私」里的使用记录 |
| 开机自启 | launchd（崩溃自动重启）；开启时 macOS 会弹「App 后台活动」通知，属正常 | 当前用户的「启动」项，守护进程负责崩溃重启；不需要管理员权限 |
| hooks 命令 | `bridge/hook.sh`（curl） | `bridge/hook.py`（用项目的 Python 环境） |
| 录屏 | 需要 `ffmpeg`（`brew install ffmpeg`） | 需要 `ffmpeg` 在 PATH 里（`winget install ffmpeg`） |

macOS 上 bridge 会读 magpie 存在自己 WebKit 本地存储里的「隐藏账号」开关，好跟着给邮箱打码。这属于别的 App 的私有数据：从终端启动时能读；launchd 自启时 macOS 会拦下（可能弹一次「数据访问被阻止」），bridge 被拦后不再尝试，改用 `buddy start` / `restart` 在终端里读到并记下的值（`bridge/state/mask.json`）。在 magpie 里改了这个开关后，在终端里运行一次 `bridge/buddy restart` 即可同步。

Windows 不需要装驱动：板子用 ESP32-S3 原生 USB，系统自带的驱动就能识别成 COM 口。

## 工作原理

```
Claude Code ──hooks──────▶ bridge（电脑，127.0.0.1:47823）──USB 串口──▶ ESP32-S3
            └─statusline──▶   汇总多会话状态 / 额度                    动画 + 额度条
```

- **状态**：Claude Code hooks（`bridge/hook.sh`，Windows 上是 `hook.py`）把事件转发给 bridge，bridge 汇总所有会话后按优先级（等待确认 > 干活 > 思考 > …）发给屏幕。
- **额度**：statusline（`bridge/statusline.sh` / `statusline.py`）收到的 `rate_limits` 转发给 bridge。额度只在终端版 `claude` 会话发出请求后更新，桌面 App 不提供。

## 像素风界面（v3）

默认是深色像素风（`POST /ui?style=0` 切回原浅色样式）：整数倍放大的像素字体、切角粗边框、实色阴影、方块进度条和方块圆环。

- 首页：X 账号与时钟、两张带品牌色的入口卡片（迷你额度条 / 今日用量柱）
- Agent / 额度 / 路由的图标是 magpie 的品牌 logo（`tools/gen_icons.py` 渲染成 16px 像素图标，主题色用于路由连线和数据包；Pi 用官网 logo，见 `tools/logo-overrides/`）
- 路由页：上滑时连线舞台跟手收起成细条，松手吸附；列表有惯性滑动
- 邮箱打码跟随 magpie 的「隐藏账号」设置
- 刷屏用 `agent_buddy/QspiFast.*`（基于 Arduino_GFX 的 QSPI 驱动改为双缓冲异步 DMA，并在发送时校色），路由列表缓存成图片按行复制

## Wi-Fi（v3.1）

首页右上角是 Wi-Fi 图标（标准扇形，按信号点亮弧数；未连接为灰色加红斜杠），点它进入设置页的 Wi-Fi 分区：

- 异步扫描附近网络，按信号排序，显示信号评级（极好 / 良好 / 一般 / 较弱）、dBm 与是否加密
- 开放网络点一下直接连；加密网络弹出像素风键盘（数字 / 字母 / 符号、大小写、显示 / 隐藏密码）
- 连接成功后网络名和密码保存在板子的 NVS 里（明文），开机自动重连；「断开」会同时忘记该网络
- 外置天线接模组左上角的 IPEX 座；可在 Wi-Fi 页对比插拔天线前后的 dBm 判断是否生效

### 无线连接 bridge（拔掉 USB 也能用）

板子连上 Wi-Fi 后，拔掉 USB（靠电池或充电头供电）时，数据会自动改走 Wi-Fi。设计见 [无线通讯方案.md](无线通讯方案.md)。

- **配对**：插着 USB 启动 bridge 时自动完成。bridge 生成密钥，只经串口发给板子（板子不接受从网络发来的这种配对），密钥存在 `bridge/state/device.json`（权限 0600）。
- **没有 USB 的电脑**：在板子上进入 设置 → 电脑 → 添加电脑（打开 2 分钟），电脑上运行 `bridge/buddy pair --wifi`。两边显示同一个 6 位验证码，核对一致后在板子上点「允许」（X25519 交换密钥，中间人没法让两边的码对上）。
- **连接方向**：
  - macOS（默认 listen）：板子主动连 Mac 上的 bridge（TCP 47824）。接受入站连接不需要「本地网络」授权，launchd 自启也能用。bridge 把本机的局域网 IP 和 `.local` 名下发给板子，Mac 换了 IP 也能用 mDNS 找回来。
  - Windows（默认 dial）：bridge 去连板子的 47824（出站不过防火墙）。依次试上次的 IP、`agent-buddy-<id>.local`、UDP 广播探测。
  - 环境变量 `AGENT_BUDDY_NET=listen|dial` 或 `device.json` 里的 `"mode"` 可以改方向。
- **多台电脑**：板子最多记 4 台（满了替换最久没连的）。同时在线时只有一台是控制者，屏幕显示它的状态，其余待命只发心跳：插着 USB 的那台 > 设置 → 电脑 里选的「首选电脑」> 先连上的那台。在「电脑」页可以看每台的状态、设为首选、移除；被移除的电脑再连会被拒绝。
- **安全**：先用共享密钥做 HMAC 双向认证，之后每一帧都用 AES-256-GCM 加密。
- **切换**：插着 USB 走 USB，Wi-Fi 连接保持着只发心跳；拔线后约 3 秒切到 Wi-Fi，插回后约 2 秒切回 USB。设置 → 关于 →「bridge」和 `buddy status` 显示当前链路（USB / Wi-Fi / Wi-Fi 待命）。
- **限制**：录屏和烧录固件仍要插 USB；bridge 需要 `cryptography`（已写进 `requirements.txt`）。Mac 开着应用防火墙时，如果弹出「是否允许 python3 接受传入连接」，点「允许」。
- **还没做**：经 Wi-Fi 录屏；多台电脑的状态合并显示（现在是一台控制、其余待命）。无线升级固件不做。

## 声音：喇叭播报 + 麦克风（v3.2）

硬件：2030 喇叭（8Ω）插板载 Speak 口（NS4168 功放，I2S BCLK=42 / LRCK=2 / DOUT=41，必须 32bit 单声道左声道）；INMP441 麦克风接 P3（SCK=IO6、WS=IO7、SD=IO15，IO16 输出低电平当 L/R），VDD / GND 取 P4 的 3.3V。

喇叭（`hw_spk.ino`）：常驻任务从 PSRAM 环形缓冲区取 16kHz PCM 播放。8-bit 音效在板上合成，语音由 bridge 用 macOS `say -v Tingting` 生成后经串口分块发送。

| Claude Code 事件 | 声音 |
|---|---|
| 发消息 | 轻轻“嘀”一声 |
| 等你确认 | “叮咚”+“Claude 需要你确认：…”；没处理每 30 秒再叮咚，最多 3 次 |
| 完成 | 上行琶音；一轮超过 20 秒时播报“任务完成，用时 X” |
| 出错 | 下行三连音 +“出错了，请看一下屏幕” |
| 5 小时额度剩 20% / 10% | 播报剩余百分比 |
| 点 Clawd | “啵” |

麦克风（`hw_mic.ino`）：开机常开，自动学习房间底噪；首页状态栏有麦克风图标（听到声音时亮绿）。Clawd 待命 / 睡觉时会对声音做反应：突然大声 → 吓一跳；有节拍的音乐 → 跟着摇摆；安静 2 分钟 → 打瞌睡。喇叭出声时不做判断。

## 设置页（v3.3）

首页右上角的状态图标（齿轮 / 麦克风 / Wi-Fi / 雷达，不加底框）：点齿轮进设置页，点麦克风直达「声音」，点 Wi-Fi 直达「Wi-Fi」，点雷达进雷达页。点右上角的日期时间切到待机时钟，在时钟页点一下回首页。仿 macOS 系统设置：左侧分区栏，右侧分组列表可上下滑动。

- 声音：音量滑块（松手试听）、静音、提示音、语音播报、完成播报门槛（20 秒 / 1 分 / 3 分 / 不播）、Clawd 听声音 + 实时输入音量
- Wi-Fi：扫描 / 连接 / 断开（原 Wi-Fi 页）
- 显示：亮度、夜里自动调暗、离开后熄屏（开着「离开时显示时钟」时白天改为调暗时钟，夜里才熄屏）、首页样式（场景 / 卡片）、离开时显示时钟
- 关于：设备、芯片、固件版本、内存、运行时长、bridge 状态

设置存在板子 NVS；声音相关的通过串口 `CFG {...}` 同步给 bridge，bridge 以板子为准。

bridge 接口：`POST /audio?voice=0|1&sfx=0|1&mute=0|1&dsec=秒`（转给板子保存，同设置页）

## 桌面首页与「你在干什么」（v3.4）

首页是一个像素小场景（`ui_scene.ino`，点 Clawd / Codex / 鱼缸进各自的 Buddy 页）：Clawd 站在书桌上，显示器显示 Claude 的状态（思考转星芒、干活滚代码、等确认闪框、完成打勾、出错打叉），喜鹊站在显示器上（有新的路由请求就扇翅膀）。窗外跟随真实时间变成白天 / 黄昏 / 夜晚，夜里台灯自动亮（点台灯可手动开关）。底部三块组件：Claude 额度、当前状态、magpie 今天。离开电脑后切成待机时钟（见下）。

Clawd 在待命时会对你做反应（`hw_act.ino`）：

| 你在干什么 | 怎么判断 | 反应 |
|---|---|---|
| 打字 | Mac 的累计按键次数（bridge 每 0.1 秒读 `CGEventSourceCounterForEventType`，不需权限，只有次数没有内容），2 秒内至少 4 下；没连 bridge 时退回麦克风听持续的敲击声 | 面前出现小键盘，你每按一下它就换手敲一下，打得快冒火花 |
| 说话 / 开会 | 板子麦克风听到断断续续的人声（或 Mac 的麦克风被占用） | 安静侧耳听，头顶静音喇叭；这段时间不播语音 |
| 音乐 | 节拍间隔均匀 | 跟着摇摆 |
| 离开再回来 | Mac 5 分钟以上没有键鼠输入 | 挥手 + 气泡「欢迎回来，离开了 N 分钟，Claude 完成了 N 个任务」 |

声音只在板子本地算音量和节奏，不录音、不外传。语音播报默认关闭（只响提示音 + 屏幕文字），可在 设置 → 声音 打开。

调试：`POST /ui?react=3`（强制显示某个反应 15 秒：2 跳舞、3 打字、4 说话、5 挥手）、`POST /ui?standby=1`（待机时钟）、`POST /back`（模拟离开 25 分钟后回来）。、`POST /say?text=…`（测试播报）、`POST /ui?vol=0..100`（音量，存板子上）、`POST /ui?mic=1`（串口打印麦克风音量，调试用）。

## Codex（v3.5）

ChatGPT 客户端 / Codex CLI 的事件也接进来了：Codex 的 hook（`~/.codex/config.toml` 的 `[[hooks.*]]`，命令为 `bridge/hook.sh codex`）把事件发到 bridge 的 `/hook?agent=codex`，与 Claude 分开统计。

- 形象：Codex 的云朵小机器人（`codex_pet.h`，按官方宠物手工整理的 32×39 像素图），头上的屏幕就是脸：待命时在 `>_` 和眯眼之间换眼神，思考时三个点，干活时坐下来抱着笔记本敲代码，等你确认时 `> ?`，完成时 `^ ^` 跳起来，点它会跳起来挥手
- 桌面首页：Codex 站在显示器和台灯之间；两个都在干活时显示器左右分屏，否则显示更忙的那个，颜色跟着活跃的一方（Claude 橙 / Codex 蓝）
- Buddy 页：左上角屋子图标右边的标题栏切换 Claude Code / Codex（样式同 magpie 页）；Codex 的额度来自 magpie（多个账号时取 5 小时剩余最多的）
- 提示音：Codex 用三角波，音色和 Claude 区分开；欢迎回来时分别报两边完成的任务数

`setup` / `buddy hooks on` 会自动写好；手动配置时每个事件一段（`async = true`）：

```toml
[[hooks.Stop]]
[[hooks.Stop.hooks]]
type = "command"
command = "/path/to/bridge/hook.sh codex"
async = true
timeout = 5
```

调试：`POST /ui?screen=1&agent=1`（打开 Codex 页）、`POST /reset`（清空所有会话）。

## DeepSeek Harness（v4.1）

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）自带一个 Claude Code hooks 兼容插件（`@deepseek-ai/dsh-hooks-claude-code`），能原样运行 Claude Code 格式的 hooks。`setup` / `buddy hooks on` 检测到装了 dsh（有 `~/.dsh` 或 `dsh` 命令）时会：

- 写一份 `~/.dsh/agent-buddy-hooks.json`，命令为 `bridge/hook.sh deepseek`（Windows 是 `.venv` 里的 python + `hook.py deepseek`），把事件发到 bridge 的 `/hook?agent=deepseek`
- 在每个 profile 的 `~/.dsh/profiles/*/cordis.patch.yml` 末尾追加一段（还没有 profile 时写 `~/.dsh/cordis.patch.yml`），挂上插件指向这份 hooks；前后有「Agent Buddy」标记行，`buddy hooks off` / `buddy uninstall` 只删这一段

```yaml
- insert:
    - id: agent-buddy-hooks
      name: '@deepseek-ai/dsh-hooks-claude-code'
      config:
        configPath: "/Users/你/.dsh/agent-buddy-hooks.json"
        defaultTimeoutMs: 5000
```

改完重启 dsh 生效（开着配置热更新时会自己重新加载）。

- **桌面版**（DeepSeek Harness.app / .exe）没有打包这个兼容插件（命令行版 dsh 带了）。`buddy hooks on` 检测到桌面版的 profile（`~/.dsh/profiles/desktop`）时，会用桌面版自带的命令行按桌面版的版本装进去（相当于 `dsh plugin --profile desktop add @deepseek-ai/dsh-hooks-claude-code@<桌面版版本>`）；装不上就不挂插件，免得桌面版启动报错。装完要退出桌面版再打开。
  - 同时装同版本的 `@deepseek-ai/dsh-hook-protocol`：它是插件的 peerDependency，pnpm 不装、桌面版也没带，不装的话 Node 会往上找到 `~/.dsh/profiles/node_modules` 里的旧版本，插件导入失败，设置 → 内置插件里显示「未运行」。
  - 桌面版只读每个 profile 自己的 `cordis.patch.yml`，不读 `~/.dsh/cordis.patch.yml`，所以插件挂在 `~/.dsh/profiles/*/cordis.patch.yml` 里。
- **DSH Desktop**（`/Applications/DSH Desktop.app`，第三方桌面版，目前只支持 macOS）：跑的是 `web` profile（不读 `desktop`），这个 profile 由它独占管理——命令行装不了插件，插件管理里只肯装声明了 `dsh.bundle` 的组合包，直接改它的 `cordis.patch.yml` 也会被重写掉。所以装了 DSH Desktop 时，`buddy hooks on` 对 `web` profile 改用组合包（官方桌面版的 `desktop` 等其他 profile 照上面的方式处理，两个可以同时开）：
  - 在 `~/.dsh/agent-buddy-bundle/` 生成一个本地组合包 `agent-buddy-dsh-hooks`：依赖同 DSH Desktop 内核版本的 `dsh-hooks-claude-code` 和 `dsh-hook-protocol`，自带挂插件的 patch，指向 `~/.dsh/agent-buddy-hooks.json`
  - **第一次要手动装一次**：DSH Desktop 的插件管理 → 安装，填 `file:/Users/你/.dsh/agent-buddy-bundle`。装完不用重启就生效
  - DSH Desktop 升级内核后，`buddy status` 会提示组合包里的插件版本过时：运行 `buddy hooks on` 更新组合包，再在插件管理里重新装一次
  - `buddy hooks off` 只删 `~/.dsh/agent-buddy-hooks.json`；组合包要在插件管理里卸载
- **Windows**：dsh 在 Windows 上用 `pwsh -Command` 跑 hook，所以命令写成 `& "…/python.exe" "…/hook.py" deepseek`。不要用 `$input |` 把事件转给 python：pwsh 会按 GBK 解码，中文会乱。

- 形象：DeepSeek logo 里的蓝鲸（`deepseek_pet.h`，32×19 像素图，眼睛、胸鳍、尾鳍、喷水由程序画），养在鱼缸里（首页墙上一个，DeepSeek 页左边一个大的，画法相同：`dsTank`）。游的时候后半身按一道往尾巴传的波上下摆，每划一下身子一顶一沉、往前一冲，身后拖泡泡，游到头掉头；隔一阵子浮上水面喷水，每三次里冲出水面一次（起跳抬头、落水低头、溅水花）；思考时同官方，一下下甩尾巴，文字是「深度求索中 · 用时 N 秒 ···」；干活时尾巴拍得飞快、头顶气泡显示正在用的工具；等你确认时瞪大眼挥胸鳍、屏幕边框闪蓝；完成时跃出水面喷大水花；点它会跳起来喷水

- **没有权限确认事件**：dsh 的审批走它自己的界面，hook 收不到，所以批准工具调用时屏幕不会提醒。只有 Agent 调用 `ask_user_question` 问你问题时，屏幕会显示「等你确认」
- 没有出错、压缩上下文、会话结束事件：这几个状态不会出现，关掉的会话 3 小时后自动清掉

## 屏幕冷启动校准

这块屏没有硬件复位脚，冷启动（拔插 USB）后屏幕芯片处于上电默认状态：固件用 `invertDisplay(true)` + `setRotation(2)` 才正常（`fixPanel()`，启动后补发并每 5 秒重设）。不同批次的屏如有差异，用 `POST /ui?inv=0|1&rot=0..3` 校准，值保存在板子上。

## magpie 面板

bridge 每隔几秒读 magpie 本地网关的只读接口（`127.0.0.1:3425/v1/magpie/*`）和 `magpie ls`，不改动 magpie 本身。

| 页面 | 数据 | 说明 |
|---|---|---|
| Agent | `magpie ls` | 每个 Agent 的模型与推理强度 |
| 额度 | `quotas/cards` | 按订阅分组，剩余百分比圆环（低于 20% 变橙） |
| 用量 | `usage/requests?limit=1` | 今天 / 7 天 / 30 天 / 全部，网关 + 会话日志 |
| 路由 | `usage?period=today`、`usage/requests?via=through` | 只看网关请求；新请求按 magpie 的方式播放光点往返 |

Agent Buddy 页的 Claude 额度也优先取 magpie 的数据（桌面 App 下同样实时）。

喜鹊动画由 `tools/gen_wag.py` 从 magpie 的 logo SVG 与 CSS 关键帧渲染生成（`agent_buddy/magpie_wag.h`）。

## 使用

### 管理命令

所有操作都通过 `bridge/buddy`（Windows：`bridge\buddy`），macOS 和 Windows 用法相同：

| 命令 | 作用 |
|---|---|
| `buddy status` | 逐项检查：进程、开机自启、串口、板子固件版本、Claude Code / Codex / DeepSeek Harness hooks、magpie、这台电脑支持哪些功能 |
| `buddy start` / `stop` / `restart` | 启动（后台运行，关掉终端也继续；意外退出 10 秒后自动重启）/ 停止 / 重启 |
| `buddy logs [-f]` | 看日志（`-f` 持续跟踪）；日志在 `bridge/state/bridge.log`，超过 5MB 自动轮转 |
| `buddy autostart on\|off` | 开机自启 |
| `buddy flash` | 烧录 `firmware/` 里的预编译固件（自动暂停 bridge 释放串口，烧完恢复；`--erase` 先整片擦除） |
| `buddy flash --build` | 先用 arduino-cli 编译当前代码再烧录（开发用） |
| `buddy build` | 编译并更新 `firmware/`（改了固件、要发给别人时用） |
| `buddy hooks on\|off` | 只注册 / 移除 Claude Code、Codex 与 DeepSeek Harness 的 hooks |
| `buddy record 30` / `snap` / `gamma 1.6` | 录屏 / 截图 / 屏幕颜色校正（同下面的工具脚本，Windows 也能用） |
| `buddy uninstall` | 停止、关闭自启、移除 hooks 与 statusline |

`bridge/` 里原来的 `start.sh`、`stop.sh`、`status.sh`、`autostart.sh`、`uninstall.sh` 仍然可以用，转调上面对应的命令；`flash.sh` 等同 `buddy flash --build`，`install.sh` 等同根目录的 `setup.sh`。

bridge 只监听 `127.0.0.1:47823`，只接受本机命令行发来的请求（浏览器网页发来的会被拒绝），不读取任何登录凭证。同时插着几块 ESP32 时，用环境变量 `AGENT_BUDDY_PORT` 指定板子的串口。

### 固件

`firmware/` 里是预编译好的固件（`manifest.json` 记录版本、编译配置和烧录地址），`buddy flash` 用 esptool 烧录 bootloader / 分区表 / 应用，不碰存设置的 NVS 分区。新板子连不上时：按住板子上的 **BOOT** 键，点一下 **RST**，松开 BOOT，再运行 `buddy flash`。

自己编译需要 `arduino-cli`（macOS `brew install arduino-cli`，Windows `winget install ArduinoSA.CLI`）。`buddy build` 会按固定版本装好 esp32 core 3.3.12 和 `GFX Library for Arduino`、`U8g2`、`TAMC_GT911`、`ArduinoJson`（第一次下载约 1GB），编译后更新 `firmware/`。Apple Silicon 上 Arduino 自带的 ctags 是 x86 版，需要从 `github.com/arduino/ctags` 源码编译 arm64 版替换（不要用 universal-ctags，生成的函数原型会出错）。

```bash
FQBN="esp32:esp32:esp32s3:PSRAM=opi,FlashSize=4M,CDCOnBoot=cdc,USBMode=hwcdc,PartitionScheme=huge_app"
arduino-cli compile -b $FQBN agent_buddy
```

注意：PSRAM 是芯片内置的 **OPI**（选 QSPI 会启动失败）；屏幕不需要 IPS 反色。

## 电池（v3.8）

电池电压经 160K / 220K 分压接 GPIO5（`hw_bat.ino`）。这个点上有充电 / 升压芯片的开关纹波，插着 USB 时接不接电池读数都一样，而充电状态脚没接到 ESP32，所以：

- **插着 USB**：状态栏显示绿色插头，设置 → 关于 →「电源」显示「外接供电（USB）」；接了电池会顺便充电。
- **只靠电池**：状态栏显示 4 格像素电池（低于 20% 变红），关于页显示电量、电压。电量按锂电放电曲线估算，只是大概。
- 拔掉 USB 时板子会重启一次（3.3V 在升压接手前掉电），属正常。只插充电头（不连电脑）时会当作电池供电，电量偏高。

## 毫米波雷达（HLK-LD2450）

雷达接 P1（UART0，GPIO44 收 / GPIO43 发，256000 波特率），开机自动切到多目标模式（最多 3 人）。`hw_radar.ino` 解析目标坐标，`ui_radar.ino` 画雷达页。

- **雷达本身能做到什么**（LD2450 手册）：最远 6 米、左右各 60°、上下各 35°，每秒 10 帧，同时最多 3 人。扫频带宽 250 MHz，距离分辨率约 0.6 米；只有 1 发 2 收，同一距离上的两个人靠角度基本分不开，所以离雷达一样远、又都不动的两个人会被报成一个点。没有灵敏度可调（可设置的只有单 / 多目标、区域过滤、波特率、蓝牙）。手册推荐挂墙 1.5～2 米高。
- **盲区**：24GHz 毫米波穿不过人体，你身后从雷达看过去是一个越往远越宽的「阴影锥」，里面的人雷达看不到。雷达离你越近盲区越大：0.3 米时半角约 36°，1 米时约 12°。所以雷达头最好离座位 0.8～1 米、高过你坐着时的肩膀、从侧面斜着看你。
- **雷达页**：120° 扇形视野，4px 方格拼成，扫描线来回摆、带余辉（开机预先算好每个方格的角度和距离，每帧只做整数比较）。左上「画面」是这张图现在画到多远（跟着最远的人在 1.5～6 米之间自动缩放），右上「雷达能看」是传感器本身的能力，两个不是一回事。你在座位上时，你身后的盲区用斜纹画出来；盲区里记着的人画成闪烁的空心框。右边三张卡片：人数、你的距离和方向、有没有人靠近。首页设置按钮里的雷达图标可以进入；Claude 和 Codex 都待命时，首页显示器上也显示迷你雷达，点显示器进雷达页。
- **滤波**：最近 5 帧里有 3 帧报了才算一个人（被挡住一半、隔帧才报一次的人也能确认）；相距 0.45 米内的两个点并成一个；跟丢后保留 1.5 秒。雷达跟丢后会把同一个人换到别的槽位重新报：新目标出现时，0.8 秒内刚丢的、1.5 米内的旧位置当成同一个人（座位上的你只认 0.6 米内的）。移动速度按最近约 1 秒的位置变化算（雷达报的速度只是朝向 / 远离雷达的那部分，横着走的人会是 0）。
- **在不在座位**：座位区（前方 1.5 米、左右各 0.8 米）60 秒没人才算离开，会切待机时钟；回来时 bridge 打招呼（座位没人超过 3 分钟）。
- **有人靠近**：你在座位上就判断——雷达 8 秒内在座位区见过你、或者 Mac 键鼠 30 秒内有操作都算，不要求这一帧看到你（你坐着不动时 LD2450 会把你跟丢，实测能整整两分钟一个目标都不报）。座位区里离座位最近的那个是你；其他人在你身后（比你远 0.3～3 米、偏离视线 1 米以内，越远越宽）或身边（离座位 1.2 米以内），并且驻足（移动速度 40 厘米/秒以下、累计约 2.5 秒）才提醒，路过的不算；连续 3 秒看不到才收起。这一帧座位区没看到你时，剩下那个人可能就是你自己，只有他是从远处（离座位 1.3 米外）走过来的、或者你正在敲键盘才算别人；在座位上被认作过你的轨迹（你起身走开）走到哪都算你。离你 0.6 米内的点（雷达把一个人拆成两个）和你正后方约两倍距离的点（反射出来的镜像）不算。座位标定后，座位区从屏幕前一直延伸到座位后 0.5 米，你往前凑近屏幕也还算你。
- **盲区记忆**：从远处走过来、走到你 1.5 米内的人，在你身后的阴影锥里、或者贴到你身边 0.9 米内后不见了，多半是被你挡住或者和你并成了一个点，不是走了：记住这个位置 15 秒，当作有人在你身后（提醒卡片写「在你身后」）。附近又看到人就交回正常判断；你离开座位或者超时就忘掉。
- **节能**：离开时暂停麦克风；离开满设定时间（5 / 15 / 30 分钟，或从不）后：开着「离开时显示时钟」就把时钟调暗到约 10%，远远还能看时间，夜里 23:00～7:00 才熄屏（早上 7 点人还没回来就亮回调暗的时钟）；关掉时钟则直接熄屏。雷达看到你、碰屏幕或 Mac 键鼠有操作时亮屏。雷达本身常开，当唤醒开关用。
- 设置 → 雷达 可以关掉座位判断和有人靠近提醒。调试：`POST /ui?radar=1`（串口打印目标，`s=` 是按位置算的速度，`F` 是从远处来的，`G=` 是盲区里记着的人）、`POST /ui?screen=5&rdemo=1`（15 秒演示数据）、`POST /ui?rmode=1`（重新设多目标模式）。
